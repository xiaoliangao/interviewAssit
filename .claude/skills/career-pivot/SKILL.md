# Career Pivot — 简历优化与职业规划工作台

## 这个 skill 在解决什么

绝大多数「AI 看简历」的输出有三个通病，这个 skill 的每条规则都是在对抗其中之一：

1. **编造**。把「协助过」写成「主导」，给没有数字的成果凭空补一个「提升 30%」。用户拿去面试会当场翻车。→ 用 [证据分级](#证据分级) 解决。
2. **正确的废话**。「你的沟通能力很强，适合销售、市场、公关」——不可证伪、不可行动。→ 用 **每个结论都要有证据引用、否决线和第一步动作** 解决。
3. **模块之间互相打架**。单独问「我适合什么岗位」和单独问「重写我的简历」，得到的是两套互不相关的定位。→ 用 **一次抽取、全程复用的职业资产清单** 解决。

所以流程是一条有依赖的流水线，不是七个独立问答：

```
简历 + 约束访谈
   └─→ 00 职业资产清单（事实底座，所有模块引用它）
          ├─→ 01 隐藏职位搜索（15 个）      ┐
          ├─→ 02 可迁移技能翻译             ├─ 探索：我能去哪
          ├─→ 03 JD 资格差距分析            ┘
          ├─→ 04 转型路径图（5 条）         ─── 决策：走哪条
          ├─→ 05 转型叙事与面试故事库       ┐
          ├─→ 06 简历定位重写               ├─ 执行：怎么拿到
          └─→ 07 30 天求职作战计划          ┘
```

## 开场：三件事做完再动手

**第一步，确认输出语言。** 问一次就够：`中文分析 + 英文简历术语（默认）` / `全中文` / `全英文`。默认跟随用户的对话语言，但简历 bullet、职位名、ATS 关键词按目标市场走——投中国公司用中文，投外企/海外用英文。用户已经说过语言偏好就别再问。

**第二步，确认模式。**
- 用户明确只要某一块（"看看这个 JD"、"把简历改成 XX 方向"）→ **单模块模式**：只跑那一个模块，但仍然先做一份**轻量资产清单**（口径统一，不然产出会和后续模块打架），不要跳过。
- 用户说"帮我做职业规划"、"我想转行"、或者只是甩了一份简历 → **全流程模式**：按 00 → 01 → 02 → 04 → 06 → 05 → 07 走，每做完一个模块停下来给用户确认一次再往下。
- 用户有明确目标岗位 + JD → 走 00 → 03 → 06 → 05 → 07，跳过 01/04（他们已经选好了，别再劝他们探索）。

**第三步，约束访谈。** 不问清约束，产出的 15 个职位有 12 个是废的。用 `AskUserQuestion` 一次问完，不要挤牙膏式一轮一问。具体问什么见 `references/00-intake.md`。

## 模块路由

用户提出的需求 → 读哪个文件。每次只读当前模块需要的，不要一次全读进来。

## 证据分级

所有产出物里的每一条关于用户的陈述，都带一个标记。这是整个 skill 的地基，模块文件会反复引用它：

| 标记 | 含义 | 能不能写进简历 |
|---|---|---|
| `[原文]` | 简历里白纸黑字写着的 | 能，直接用 |
| `[重述]` | 事实完全不变，只换成目标行业的说法 | 能，但要让用户逐条确认译法没失真 |
| `[待补]` | 需要用户提供数字或细节才成立 | **不能**，必须留 `__（需你补充：某某数字）__` 占位 |
| `[推断]` | 基于常识的合理推测，简历里没有依据 | **绝对不能**，只出现在分析文字里，且必须标出来 |

**永不编造**：职位头衔、任职时间、公司名、团队规模、任何数字、学历、证书、技术栈熟练度。缺数字就留占位符并汇总成「请你补充」清单——一个诚实的占位符比一个漂亮的假数字有价值一万倍，因为后者会在面试第二轮被问穿。

**薪资和市场数据**：任何薪资区间、招聘热度、行业趋势，必须紧跟来源和时效标注。有 `WebSearch` 就去查关键职位并附链接；没有就统一写 `⚠️ 模型估算（截至训练数据），未核实 → 请在 <平台> 搜索 <关键词> 自行验证`。不给精确到个位的假数字。完整规则见 `references/evidence-and-data.md`。

## 反废话检查

写完任何一个模块，回头扫一遍，这三类句子直接删掉重写：

- **不可证伪**：「你有很强的领导力」→ 改成「你带过 8 人跨职能团队 [原文·经历B]，这是 XX 岗位的硬门槛」
- **不可行动**：「建议学习数据分析」→ 改成「两周内用你手上的 XX 数据做一个 Y 分析，产出物是能写进简历的这一行：`...`」
- **没有反面**：任何推荐都要配一条**否决线**（什么情况下这条不适合你），任何路径都要配**退出条件**（第几周没有什么信号就该止损）。只会说「可以努力」的建议等于没建议。

## 产出物

写文件，不要只在终端里刷。默认写到当前目录的 `career-report/`（用户指定别处就听用户的）。文件名固定，语言无关，方便复跑时覆盖：

```
career-report/
├── README.md          目录索引 + 一页纸结论 + 待用户补充清单
├── 00-inventory.md    职业资产清单
├── 01-roles.md        15 个职位 + 排序矩阵
├── 02-skills.md       可迁移技能表 + 术语翻译表
├── 03-gap.md          JD 差距分析（多个目标岗位就加后缀 03-gap-<岗位>.md）
├── 04-paths.md        5 条转型路径 + 对比表
├── 05-narrative.md    转型叙事 + STAR 故事库
├── 06-resume.md       重写后的 summary/bullets + 原文对照表
└── 07-plan.md         30 天作战计划 + 追踪表
```

每个模块跑完，在终端只讲**三句话**：最重要的一个发现、一个需要用户决策的岔路口、下一步建议做哪个模块。细节都在文件里，别在终端复述一遍。

`README.md` 每次跑完都更新，尤其是「待你补充」清单——把散落在各模块的 `[待补]` 占位符汇总到一处，用户一次性填完，比来回追问高效得多。
