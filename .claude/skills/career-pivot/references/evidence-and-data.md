# 贯穿全流程的硬规则

每个模块开工前都适用。SKILL.md 里有摘要，这里是完整版和边界情况。

## 1. 证据分级

| 标记 | 判定标准 | 用途边界 |
|---|---|---|
| `[原文]` | 简历原文能逐字对应 | 简历、cover letter、面试话术，全部可用 |
| `[重述]` | 事实、范围、归因都不变，只换词 | 可用，但必须在 `06-resume.md` 的对照表里列出来让用户逐条确认 |
| `[待补]` | 事实成立，但关键数字/细节简历里没有 | **简历里必须保留占位符**，不得填入猜测值 |
| `[推断]` | 简历没依据，靠行业常识推的 | **只能出现在分析段落**，且句中要出现「推测/可能/通常」这类词 |

### 重述的红线

「重述」和「夸大」只隔一层窗户纸，判断标准是**如果 HR 打电话给前雇主核实，说法还站得住吗**：

| 原文 | ✅ 合法重述 | ❌ 越界 |
|---|---|---|
| 协助经理完成季度预算 | Supported quarterly budgeting cycle for a $X team | Owned quarterly budget planning |
| 负责客服邮件回复 | Managed customer inquiry resolution across email channel | Led customer experience strategy |
| 参与新系统上线 | Contributed to the rollout of a new XX system | Drove end-to-end migration to XX |

归因动词是最容易出事的地方。简历说「参与/协助/支持」，改写后就不能变成「主导/负责/驱动」。碰到用户说"其实是我主导的，简历没写清楚"——那就让用户自己确认后升级，并在对照表里标成 `[用户确认升级]`，责任归属清清楚楚。

### 占位符写法

```
Reduced ticket backlog by __（需你补充：百分比或绝对数量）__ within __（需你补充：时间跨度）__
```

不要写「显著减少」「大幅提升」来绕过——模糊形容词在简历里等于没有，招聘方会直接跳过这一行。宁可空着让用户填。

所有占位符同步汇总到 `career-report/README.md` 的「待你补充」清单，按**回报率排序**（填了这个数字能救活几条 bullet），让用户知道先填哪个最划算。

## 2. 永不编造清单

以下内容只能来自简历原文或用户明确告知，不得推断、不得"合理补全"：

职位头衔 · 任职起止时间 · 公司名称与行业 · 团队/下属规模 · 预算或营收数字 · 任何百分比与增长率 · 学历与院校 · 证书及有效期 · 技术栈与熟练度等级 · 语言水平 · 获奖

简历有 gap 期、降级、短期任职，**如实记录在资产清单的「空白与风险」里**，然后在 `05-narrative.md` 里正面设计应答脚本。掩盖不了，只能准备好怎么谈。

## 3. 市场数据规则

薪资、招聘热度、行业趋势这类外部数据，是 LLM 最容易一本正经胡说的地方，也是用户最容易据此做错决定的地方。

**优先用 `WebSearch`**（这个 skill 的产出质量很大程度取决于此）。至少检索：
- 全流程模式：01 模块推荐的前 5 个职位的薪资区间和招聘量
- 单模块模式：当前模块直接涉及的职位

搜索时带上用户的**地点**和**年份**（如 `产品经理 薪资 上海 2026` / `solutions architect salary Berlin 2026`），泛泛搜全国均值对个人决策没有用。

**标注格式**（每个数字后面都要跟）：
```
¥35–50K/月 〔来源：<平台/链接>，数据时点：2026-08，样本：<城市/年限>〕
```

**没有搜索能力时**，统一这样写，一个字都不要少：
```
⚠️ 模型估算，未核实 → 请在 <具体平台> 搜索 <具体关键词> 验证
```
并且给**区间而非点值**，区间宽度要诚实地反映不确定性。宁可写「25–60K，跨度大因为这个岗位在不同行业差异极大」，也不要写一个看起来很精确的「42K」。

**市场需求**不要只说「需求旺盛」。给可验证的信号：
- 某平台当前在招岗位数量（带搜索词，用户能自己复现）
- 趋势方向（增长/持平/收缩）及判断依据
- **AI/自动化替代风险**（未来 3–5 年，这是 2026 年做职业规划绕不开的变量，必须每个岗位都评一句）

## 4. 反废话检查（交付前最后一遍扫描）

逐句问三个问题，任何一句答不上来就重写：

1. **这句话能被证伪吗？** 「你适应能力强」不能。「你在 18 个月里换了 3 个业务线且每次都在 3 个月内独立交付 [原文·经历C]」能。
2. **用户读完知道明天做什么吗？** 「建议提升数据能力」不知道。「本周把 <具体数据源> 拉出来做一个 <具体分析>，周日前产出一页图表」知道。
3. **有没有反面？** 每个职位推荐配否决线，每条路径配退出条件，每个 JD 分析给明确的投/不投判断。全是鼓励的建议对用户是有害的，因为它把筛选成本全推给了用户。

## 5. 语气

用户可能正处在失业、被裁、职业倦怠的状态里。既不要用廉价的鼓励（"你的背景非常出色！"），也不要居高临下地诊断。就事论事地说清事实、代价和选项，把决定权交回给用户——这是对处境艰难的人最大的尊重。

遇到客观上难的情况（长期 gap、行业整体收缩、年龄门槛），**直接说出来**并给应对方案，不要粉饰。用户需要的是能用的地图，不是好听的话。
